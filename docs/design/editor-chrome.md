# Editor chrome and rule descriptions

Issue [#89](https://github.com/fran2889/game-cat/issues/89) aligns the Smart Collection editor's rail
chrome and preview affordances with the prototype. The v1 specification leaves component appearance
to Mantine: [§7.10](../specs/game-cat-v1.md#710-visual-reference) says surfaces, colour tokens,
spacing, and branding are not contractual. This note records the values chosen here so a future
change is deliberate rather than accidental. The end-to-end tests assert the structure and the
accessible names, not these exact pixels.

## Rail header

| Property    | Value                                                                        |
| ----------- | ---------------------------------------------------------------------------- |
| Eyebrow     | `SMART COLLECTION`, 12px, uppercase, `gray.5`, weight 600                    |
| Status dot  | 6px circle; saved `green-6`, saving and unsaved `yellow-6`, failed `red-6`   |
| Status text | 12px, `gray.5` (`red` when failed), `role="status"` and `aria-live="polite"` |
| Header row  | Eyebrow left, dot and status right, one line; 5px between dot and label      |
| Draft       | No dot or status until the first explicit Save                               |

The dot is decorative (`aria-hidden`); the label carries the state. The match count reads
`N games match · updates as you edit`, with `1 game matches` for a single match. Only the count and
noun sit in the `aria-live` region, so the static hint is not re-announced.

## Rule rows

- Descriptions are generated by the required `describe()` on each Field definition in
  `src/shared/rules.ts`, with `<Label> <operator>…` as the draft-row fallback.
- The description is 12px, `gray.5`, right-aligned, clamped to two lines, and takes the space between
  the prefix buttons and the remove action.
- Add rule keeps the visible name "Add rule"; its 14px plus icon is decorative.
- The rule-row remove action uses the 14px `IconX`; Delete is a 15px `IconTrash` `ActionIcon` with the
  existing "Delete" name and confirmation dialog.
- The prefix callout is a blue light `Alert` with a 16px info icon. It keeps the prefix counts and the
  global explanation.

## Deliberate deviations

- **No footer Save.** Autosave owns saved Collections, so a second footer Save would duplicate the
  source of truth. Its useful copy moved to "Changes save automatically · Rules save as a whole
  array."
- **The callout is a note, not an alert.** Mantine's default `role="alert"` would announce the static
  prefix explanation on mount and after every edit. The editor passes `role="note"`.
- **Singular match count.** `1 game matches` keeps the sentence grammatical; the mockup's
  `N games match` template is used for every other count.
- **Icons beyond Delete.** The issue asked for the delete icon; Add rule and the rule-row remove
  control adopt the shell's Tabler set so the rail does not mix glyph and icon vocabularies.
- **Select shown matches the Library.** The preview button disables at "All shown selected" and
  clearing stays in the shared selection bar rather than introducing a page-scoped "Clear shown".

The editor tests in [`tests/e2e/editor-parity.spec.ts`](../../tests/e2e/editor-parity.spec.ts) pin the
header state, the rule descriptions, the shown-page selection, and the Delete affordance.
